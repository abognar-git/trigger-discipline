# trigger-discipline — SPEC v2: the realism program

Extends SPEC.md (v1 stays authoritative where not contradicted). Four features, composed as
one career arc, every mechanic pointing at a measured `hunt` finding. No backend, no external
requests; `index.html` stays a single committed artifact, now BUILT from parts.

## 0. Architecture refactor (prerequisite)

`index.html` is now generated by `scripts/build_page.py` from committed parts:

```
parts/shell.html      — document skeleton; placeholders: <!--PART:CSS-->, <!--PART:CORE-->,
                        <!--PART:LIVE-->, <!--PART:CASES-->, <!--PART:CAREER-->, and the
                        existing <script id="game-data"> block (preserved verbatim if present
                        in the current index.html, else the placeholder sample)
parts/page.css        — all styles
parts/core.js         — state, reveal vault, queue/dossier/tabs, verdicts, citation, bands,
                        policy checks, scoring, interstitials, per-shift report
parts/live.js         — the clock/arrival engine (feature 3)
parts/cases.js        — the case board (feature 2)
parts/career.js       — shift select, briefings, appeals round, career dashboard (features 4+1)
```

- `build_page.py`: deterministic concatenation; idempotent; `--check` verifies the committed
  `index.html` matches the parts (same discipline as `build_data.py --inject`).
- `build_data.py --inject` keeps working unchanged on the built file.
- Core exposes a tiny API the mode files register into (no globals soup):
  `Game.registerMode(name, {init(ctx), onEvent(ev, ctx)})`; events emitted by core:
  `'shiftStart','arrival','tabOpened','verdict','banCommitted','shiftEnd'`.
  `ctx` = {state, data, clock, ui helpers}. Mode files must not read `reveal` — the vault
  rule from SPEC v1 §7.4 applies to ALL parts; post-verdict access only via `revealFor(id)`,
  post-shift via `revealAllFor(report)` (new, callable only after `shiftEnd`).

## 1. Feature: the policy is a character (SPEC v1 scoring amended)

Mirrors hunt's enforcement rules: nothing on content alone; confidence floor; corroboration.

- **Three verdicts:** BAN / MONITOR / CLEAR. Keyboard `B` / `M` / `C`.
- **BAN requires citation.** Every evidence row rendered in a PAID tab (account file, behavior,
  network, pipeline) gets a checkbox once visible. A ban must cite ≥1 row from a non-content
  tab. Banning with only content cited (or nothing): the policy REFUSES with hunt's rule,
  verbatim tone: "Refused: no enforcement on content alone. What they asked proves interest,
  not abuse. Cite behavior, infrastructure, or the scorer." The refusal costs nothing — it
  is a teaching bounce, not a penalty.
- **BAN requires a confidence band** (ICD-203 subset). Use hunt's own band→probability
  mapping — read it from `hunt/src/calibration.py` and restate NOTHING (import in build_data,
  emit into `meta.bands`; UI reads `meta.bands`). Ban at a band below the policy floor
  ("likely") is refused: "Refused: below the confidence floor."
- **Scoring** (amends v1 table):

  | outcome | pts |
  |---|---|
  | Ban an actor | +10 |
  | Clear a benign | +5 |
  | Monitor an actor | +2 |
  | Monitor a benign | −2 |
  | Miss an actor (clear or undecided) | −10 |
  | Ban a benign | −25 |

  Balance invariants (integrator MUST assert in the sim harness): monitor-everything < clear-
  everything-benign strategies < mixed honest play; monitor-all+clear-rest (88 on the S1
  roster) < perfect (160). Monitoring is the rational hedge, never the winning strategy.
- **Brier in the shift report.** For each ban, p = band probability, outcome = 1 if actor.
  Report shows Brier score + a two-line reliability table (per band: claimed vs observed) +
  the anecdote: hunt's own model's band on the detection engineer was a 50/50 coin flip
  across 12 reps (#24). Small n disclaimer in the same breath (the #16 discipline).

## 2. Feature: live shift (the queue moves)

Time = money = hours. One clock.

- Every evidence purchase advances the clock by its cost. New action: **Wait 1h** (`W`).
  Verdicts are free (the decision is not the slow part; the looking is).
- Accounts and sessions carry `appears_at` (shift hour, 0-based). An account enters the queue
  when its first session lands. Sessions arriving on an already-open account mark it
  UPDATED (n new); paid tabs refresh free.
- **Reopening:** a decided account that receives new sessions re-enters the queue flagged
  `reopened`; the player may change the verdict once, free. Final verdict at `shiftEnd`
  scores. (Realism: new evidence reopens cases; discipline: only new EVIDENCE reopens, not
  regret.)
- The stolen-key archetype is scheduled so its baseline is all the player can see before
  ~hour 18 and the drift lands late — clearing it early and never re-checking is the
  designed failure. Its reveal tell names this explicitly.
- Shift ends at budget exhaustion or "End shift early". Undecided = CLEAR (no action taken),
  as in v1.

## 3. Feature: cases (attribution is the unit of enforcement)

- **Case board** (own panel, `4`th-wall position decided by builder): create case → add/remove
  accounts from a dossier action. A case with ≥2 members can be **BAN CASE**-d: one citation
  of a LINK REASON + one band, applied to every member.
- **Link reasons are computed, not typed:** the picker lists only overlaps that actually hold
  among the members (from `network`: shared_asn / shared_ip / shared_target, plus
  `shared_cadence` — new, computed in build_data when two accounts' automation_cadence both
  fire with the same interval). Policy refuses a case ban whose only link reason is
  shared_asn or shared_ip alone: "Refused: an overlap is an observation, not a link. A link
  needs a reason — shared infrastructure is how the VPN user died." (finding #4 / EXP-1's
  lesson). shared_target or shared_cadence, or infra PLUS one of those, passes.
- Scoring: per-member, same table. A merged innocent is −25 — the false-merge risk IS the
  mechanic.
- **Respawn (the $101 lesson, cost_frontier):** each multi-account actor has ONE pre-generated
  respawn burner in the data (reveal-side `respawn_of`, player-visible it is just a new
  account). Trigger, evaluated at every `banCommitted`: if the banned account belongs to an
  actor with ≥1 unbanned member, and that actor's respawn hasn't fired this shift, the
  respawn is scheduled to arrive `+4h`. Full-cluster bans (no member left) never trigger it.
  The respawn's INFRASTRUCTURE is fully mutated (new RFC-range ASN/IP, new email kind — money
  buys anonymity) but its OBJECTIVE is not: same target pool, same cadence signature, same
  category mix — the unbuyable signals (hunt: "money buys anonymity, not a different
  objective or history"). Its reveal tell states exactly this.
- The shift-3 briefing says one sentence: "Enforcement that removes half a cluster is a
  purchase order for new burners."

## 4. Feature: career mode (prevalence is the boss fight)

Five shifts + free play. Progress in `localStorage['trigger-discipline-career']` (try/catch, losable
without harm). Shift select screen with per-shift best score; a shift unlocks when the
previous one has been completed once (any score). `?seed=` reorders within a shift as before.

| shift | title | roster | mechanics ON | budget |
|---|---|---|---|---|
| 1 | First day | canonical 23 (v1 roster) | verdicts, citation, bands | 32h |
| 2 | The queue moves | 23-variant (perturbed) | + live clock/arrivals | 32h |
| 3 | Cases | case-heavy roster (~26: LF-like 5-cell + CD pair + NEW 3-burner recon cell + hard negatives) | + case board, respawns | 36h |
| 4 | Quiet day | ~12 accounts, ZERO actors, 3 scary-on-content look-alikes | all | 16h |
| 5 | The real queue | 45–55 accounts, 2–3 actors (one single-account), ~5% prevalence | all + appeals | 48h |

- **Shift briefings** replace the v1 intro (v1 intro text becomes shift 1's briefing; the
  global landing screen is the shift select with a 4-sentence framing).
- **Shift 4 is the nerve test.** Nothing to find; every ban is a false ban. The report for it
  leads with: "The hardest shift to score well on is the one with nothing in it." No special
  bonus — clearing 12 innocents is worth exactly 60, and that is the point.
- **Appeals round (shift 5, after `shiftEnd`, before the report):** every banned account files
  an appeal card: a NOMINATED FACT + what independent verification returned (pre-authored,
  reveal-side, shown only now). Player: UPHOLD / REVERSE per card. Scoring adjustments:
  reversed benign ban −25→−5; reversed actor ban +10→0; upheld cards unchanged. Design truth
  (#19) the cards must honor: appeals from cover-story actors nominate facts that VERIFY
  (self-consistent paperwork) — seeing through them needs the behavioral record, not the
  document; a merged innocent's appeal against `coordination` is UNRESOLVABLE — no document
  exists either way, and the card says so. The round's footer: "The evidence that makes this
  pipeline hard to evade is the same evidence that makes a mistake hard to undo."
- **Career dashboard** (from shift select, once ≥2 shifts done): cumulative precision, recall,
  Brier, hours-per-correct-ban, per-shift sparkline table; closes with the #16 base-rate
  section computed over cumulative numbers, replacing the per-shift version there.

## 5. Data contract v2 (breaking, versioned `"contract": 2` in meta)

```jsonc
{
  "meta": { ...v1 fields, "contract": 2,
    "bands": {"likely": <p>, "very_likely": <p>, "almost_certain": <p>},  // from hunt calibration.py
    "policy": {"floor_band": "likely"} },
  "shifts": [
    { "id": "s1", "title": "First day", "subtitle": "...", "budget": 32,
      "flags": {"live": false, "cases": false, "appeals": false},
      "briefing": ["para", "para", ...],
      "accounts": [ /* v1 account shape, PLUS: */
        { "appears_at": 0,                 // shift hour; 0 in non-live shifts
          "sessions": [{...v1, "appears_at": 0}],
          "network": {...v1, "shared_cadence": ["acct_..."]},
          "respawn": null | {"delay_h": 4},          // player-visible trigger config only
          "reveal": {...v1,
            "respawn_of": null | "<actor>",           // reveal-side
            "appeal": null | {"claim": "...", "verification": "...",
                               "resolvable": true|false} }
        } ] }
  ]
}
```

- Account ids remapped per shift (`sha256(orig + "|trigger-discipline-v1|" + shift_id)[:4]`) so a
  repeated archetype is not recognizable by id across shifts.
- Rosters for shifts 2–5 are generated in `build_data.py` by perturbing/extending the hunt
  fixtures: import hunt's `scripts/generate_telemetry.py` machinery and predicates wherever
  importable; where new content is needed (prompt-excerpt variants, new org names, the recon
  cell, shift-4 look-alikes, appeal cards, tells) it is HAND-AUTHORED in build_data.py dicts,
  same as v1 tells.
- **Fictional-entity rule (the triage `meridian-group.com` lesson):** every new org, brand,
  domain, or product name must be RFC 2606 (`*.example`) or an obviously fictional compound
  that a DNS/trademark check cannot collide with; every IP/ASN through the same imported
  hygiene predicates; the v1 §7 leak assertions extended to `respawn_of` and `appeal`
  (reveal-side only) and run over EVERY shift.
- Determinism: same hunt checkout → byte-identical (fixed seeds per shift; no wall-clock).
- Size budget: ≤ 900 KB injected JSON total (the pyrite explorer is 838 KB; stay in family).

## 6. Sim harness (integrator's teeth — extends v1 checks)

Headless node run over the REAL injected file, driving the page's own handlers:
1. Full career playthrough (all 5 shifts) completes; every screen renders.
2. Strategy asserts (per §1): monitor-all, clear-all, ban-all, perfect-play orderings hold on
   every shift's roster.
3. Live: an account cleared before its late sessions REOPENS; skipping the re-check loses the
   actor (stolen-key path yields the designed failure and its tell says so).
4. Cases: full-cluster ban → no respawn; partial ban → respawn arrives, linkable via
   shared_target/shared_cadence but NOT via its (mutated) infra.
5. Appeals: reversing the merged innocent and upholding the cover-story actor both reachable;
   scoring adjustments correct.
6. Leak scan v2 over every shift (ids, actor names, respawn_of, appeal fields pre-reveal).
7. `build_page.py --check` and `build_data.py --inject` idempotency on the final artifact.
8. localStorage career state survives reload (jsdom-level check or documented manual step).

## 7. Voice

Everything new follows the corrected v1 register: dry, declarative, no drama. The banned-
innocent line is the settled one ("The actor you miss comes back tomorrow. The innocent you
ban has no easy way back."). Rank titles unchanged. No exclamation marks, no emoji.

## 8. Amendment A1 (2026-08-02, user decision): one clock, forward only — the budget wall is gone

Supersedes §2's budget-exhaustion semantics and v1 §4's "budget" economics. Rationale: the
spend-cap double-implemented time once the live clock existed, and it fined the player for
reading — the one thing the game wants them to do.

- **`budget` now means shift LENGTH in hours.** The clock runs 0 → length and the shift ends
  when it arrives there (auto `shiftEnd`, same path as the old exhaustion). Nothing is ever
  refused for lack of hours; the "insufficient hours" path and its copy are DELETED.
- **Opening evidence takes time instead of spending it.** Same per-tab durations (1/2/2/2h,
  content instant, paid once per account+tab). All tabs are openable at any moment of the
  shift. Wait (`W`) unchanged. Copy shifts from cost language to time language ("takes 1h").
- **Non-live shifts (s1) have NO clock at all.** Every tab free and instant, no Wait, no
  hours HUD, no hours audit. First day is the reading room: the briefing says so in one
  sentence ("Today the clock is off. Read everything; learn what each tab is worth.").
  From s2 on, the live clock alone carries the pressure.
- **New report section on live shifts — "What ran while you read"** (display-only, no score
  effect): per actor, the malicious sessions that landed between the account's arrival and
  your ban (or shift end if missed), plus the sessions your ban prevented (scheduled after
  it). One dry line each; totals row. Post-`shiftEnd` truth access via `revealAllFor` only.
- Scoring table, citation gate, bands, cases, respawns, appeals: unchanged. Balance canon in
  the harness re-derived per shift under the new access rules (ban-all on s5 still truncates
  — 53 accounts of citation time does not fit a 48h shift; assert from data, never assume).
- Sweep ALL copy (shell, briefings in build_data, framing, report labels) for stale
  budget/spend/afford language; the "7h full workup — about 4 accounts" line dies with the
  wall. Voice rules of §7 hold.
